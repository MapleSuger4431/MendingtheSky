# 架构说明（MendingtheSky / 女娲补天）

> 目的：让你在 10 分钟内看懂「这个项目由什么组成、一次操作会经过哪些代码、要加东西该改哪里」。
> 本文只描述**当前实现**，设计决策与规则来由见 `Docs/设计评审与定稿.md`。

---

## 1. 一句话架构

**单场景 + 一组 Manager 组件 + 由 `GameManager.Update` 集中驱动的 Tick**，没有事件总线、没有依赖注入、没有 ECS。
管理器之间用 `[SerializeField]` 在 Inspector 里互相引用（全部挂在场景的 `Phase1Root` 物体上）。

```
SampleScene
├── Main Camera
├── GameRoot        ← 9 个管理器组件都挂在这里（见 §7）
├── Background
├── BasketArea      ← 背篓区触发器（BoxCollider2D）
├── PotArea         ← 锅区触发器（BoxCollider2D）
├── Canvas          ← HUD / 暂停 / 失败 / 胜利 四个面板（见 §7）
└── EventSystem
```

## 2. 启动时序

```
Unity 加载场景
  → 各组件 Awake
        GameManager.Awake  → L10n.Init(localizationDatabase)   // 本地化必须最早
        UIManager.Awake    → 绑定按钮 onClick
  → 各组件 OnEnable
        LocalizedText.OnEnable → 订阅 L10n.OnLanguageChanged 并刷新一次
  → GameManager.Start
        StartGame() → StartLevel(levelConfig)
```

`StartLevel(config)` 做 7 件事（见 `GameManager.cs`）：

| 步骤 | 动作 | 相关类 |
|---|---|---|
| 1 | 生成网格与洞口 | `GridManager.GenerateLevel` |
| 2 | 重建缺口/边界视觉 | `GridVisual.Init` + `RefreshAll` |
| 3 | 初始化灵气并订阅归零事件 | `QiManager.Init` |
| 4 | 设置锅容量并清空 | `PotManager.SetMaxCount` / `Clear` |
| 5 | 按洞切石、发到背篓（含冗余补给） | `InventoryManager.GenerateInitialInventory` |
| 6 | 复位拖拽/暂存/预览 | `DragController.ResetAll` |
| 7 | 显示 HUD，进入 `Playing` | `UIManager.ShowHUD` |

## 3. 帧循环与状态机

只有 `GameState.Playing` 时 `GameManager.Update` 才推进：

```csharp
qiManager.Tick(dt);        // 按空缺格扣灵气，归零 → OnQiEmpty → Lose
gridManager.Tick(dt);      // 每 5 秒尝试补洞（未闭合洞数 < holeCount 且配额未用完）
potManager.Tick(dt);       // 推进锅内灵石的熬煮进度
```

状态机（`GameState`）：`Idle → Playing ⇄ Paused → Win / Lose`。
暂停用 `Time.timeScale = 0` + 集中 Tick 双保险；恢复/重开时恢复 `timeScale`。

## 4. 一次「放置灵石」的完整调用链

```
DragController.Update                    // 输入：鼠标按下/拖动/抬起，滚轮或 R 旋转
  ├─ TryPickUp()                         Physics2D.OverlapPointAll 取最高 sortingOrder 的灵石
  ├─ StartDrag()                         切 Kinematic（不能用 simulated=false，会退出物理查询）
  ├─ UpdatePreview()                     MatchChecker.GetPreviewHint → GridVisual.ShowPreview
  │     └─ 绿=几何可放且清单还有该形状额度 / 黄=额度用完或形状不在清单 / 红=不可放
  └─ OnMouseUp()                         按优先级处理落点：
       ① 锅区    → PotManager.TryAddLingShi（InBasket → Cooking）
       ② 网格    → MatchChecker.GetMatchedHole → GridManager.FillCells
       ③ 背篓区  → InventoryManager.ReturnToBasket
       ④ 落空    → 暂存（Cooked + 半透明悬浮）
```

`GridManager.FillCells(ls, row, col)`：

```
逐格写 grid=1 → Hole.NotifyCellFilled → LingShi.MarkPlaced → Hole.AddLingShi
  → Hole.IsFull() ? CheckHoleClosed(hole)
```

`GridManager.CheckHoleClosed`：

```
IsFull 且未闭合
  → Hole.MatchesPlacedShapes()        // 洞内每块「非冗余」灵石都要能抵扣清单里一条同签名条目
       不通过 → Debug.Log 提示「可能有其他洞口需要的形状」，不愈合
       通过   → MarkHoleClosing
                  → grid=2（闭合中，不再扣灵气）
                  → LingShi.DisableInteraction（锁定）
                  → GridVisual.PlayClosingAnimation（1 秒淡出，暂停会冻结）
                  → FinishHoleClosing
                        → Hole.GetQiReward（按灵石类型求 qiValue 和）
                        → 销毁洞内灵石
                        → 格子恢复 -1、移除洞、GridVisual.RefreshAll
                        → GameManager.OnHoleClosed（加灵气、已填洞 +1、检查胜利）
```

## 5. 数据模型

| 类 | 是什么 | 关键字段 |
|---|---|---|
| `LevelConfig`（SO） | 一张关卡的参数表 | 网格行列、洞数量/大小/合并概率/补洞间隔、灵气初值与消耗、锅容量、初始旋转概率、灵石类型池 |
| `LevelDatabase`（SO） | 关卡数组 | `LevelConfig[] levels` —— **当前未接入，见 §9** |
| `Hole`（纯 C#） | 一个洞口 | `cells`、`boundaryEdges`、`nowCellCount`、`placedLingShi`、`requiredShapeEntries`、`isClosing` |
| `LingShi`（MonoBehaviour） | 一块灵石实体 | `shape`、`state`、`sourceHoleId`、`typeConfig`、双层方块渲染 |
| `LingShiShape`（纯 C#） | 形状 + 4 个预计算旋转 | `baseCells`、`rotations`、`rotationSteps` |
| `ShapeCutter`（静态） | 把洞切成一组块 | `Cut`（贪心 + 30 次重试）、`CanTile`（可解性搜索）、`GetCanonicalSignature`（旋转无关签名） |
| `ShapePoolConfig`（SO） | 可用形状池 | `ShapeEntry[]`（cells + weight） |
| `LingShiTypeConfig`（SO） | 一种灵石 | 三种状态的贴图、`cookTime`、`qiValue` |

**形状清单（requiredShapeEntries）**：生成洞时，`ShapeCutter.Cut` 把这组格子切成 N 块，
每块登记一条清单。它有两个用途：
1. **预览额度**：绿=清单里还有这个形状；放进去少一个，抠出来恢复一个；
2. **愈合判定**：洞内每块非冗余灵石的形状都要能抵扣一条；冗余灵石（`sourceHoleId = -1`）不参与。

因为清单本身就是从这组格子切出来的，所以「按清单填满」在数学上一定可行（`CanTile` 可验证）。

## 7. 场景与 UI

**`GameRoot` 上挂的组件**（整套管理器都挂在这一个物体上）：

```
GridManager, GridVisual, InventoryManager, DragController,
PotManager, QiManager, GameManager, UIManager, DebugCheats
```

**Canvas 结构**（全部直接摆在场景里，没有 prefab）：

```
Canvas
├── HUDPanel            QiBar / QiText / LevelText / StatusText
├── PausePanel          Dim / Title / ResumeButton / RestartButton / BackButton
│                       / PreviewToggleButton / LanguageButton
├── LosePanel           Dim / Title / LoseText / LoseRetryButton
└── WinPanel            Dim / Title / WinText / WinRetryButton
```

各面板由 `UIManager` 的 `[SerializeField]` 直接引用；静态文案靠挂在 TMP 上的 `LocalizedText`
（配 key），带参数的文案（关卡号、结算进度、语言名、预览开关）由 `UIManager.RefreshLocalizedTexts` 生成。

**UI 是阶段 4（commit `9029964`）做的**：随 HUD、暂停、失败/胜利面板的需求一起落地；
多语言（`a4a797d`）在此之上加了语言按钮与文案表。它没有独立的「UI 阶段」。

## 9. 已知技术债（有意识保留，不是遗漏）

| 项 | 影响 | 计划 |
|---|---|---|
| `LevelDatabase` 无资产、无引用 | 多关卡/选关没有地基，`GameManager` 直接硬挂单关 | 做无尽模式时接入 |
| `GridManager` 780 行 | 网格、洞生成、合并、填格、结算、调试入口都在一个类 | 有新需求时再拆 `HoleSettlement` |
| UI 无 prefab | 面板只能改场景，复用/换皮成本高 | 有第二个场景时再做 |
| 填满但清单不符时不扣灵气 | 玩家可「填满卡住」冻结倒计时（`GetUnfilledCellCount` 有 TODO） | 按用户要求暂时保留 |
| 冗余灵石只在开局补一次 | 中后期不会自动补充「万能块」 | 若需要再改 `TryAddRedundant` 的调用时机 |
